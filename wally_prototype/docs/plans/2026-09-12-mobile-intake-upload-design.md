# 手機收件上傳設計

## 目標

為黑客松 Demo 新增一個手機優先的「案件收件」頁面，讓承辦人模擬拍照或選取紙本訴願文件。案件只有在 AI 模擬辨識完成、承辦人確認並建立後，才會出現在「我的案件」。

## 方案

採用獨立 `/intake` 頁面，並在全域側邊欄加入「案件收件」。相較於在「我的案件」使用彈窗，獨立頁面更符合手機現場收件情境；相較於完整掃描精靈，單頁流程較適合黑客松 Demo。

## 互動流程

1. 承辦人從手機開啟「案件收件」。
2. 選擇相片或 PDF，可一次加入多個檔案。
3. 系統以短暫等待動畫模擬上傳與 AI 文件辨識。
4. 頁面顯示辨識出的訴願人、案由、原處分機關、文件清單與完整性提示。
5. 承辦人確認後按「建立案件」。
6. 建立成功後顯示成功狀態與「前往我的案件」。此時新案件才加入案件佇列，階段為「待人工初檢」。

## 資料與狀態

- 不串接真正 OCR、後端或雲端儲存。
- 使用既有 Workflow Context 與 sessionStorage 保存 Demo 狀態。
- 預先準備一筆完整的 Demo 案件資料，建立前由可見性狀態隱藏；建立後才納入案件數量、篩選與清單。
- 「重設 Demo」會再次隱藏這筆收件案件。

## 介面與錯誤處理

- 手機版以單欄、大型點按區與底部主要動作為主，桌面版維持與既有工作台一致的卡片排版。
- 上傳區接受圖片與 PDF；未選檔時不可開始辨識。
- 顯示檔名、檔案數量與移除控制。
- 模擬辨識完成前不可建立案件；重複建立時不新增重複資料。

## 驗證

- 驗證未上傳、辨識中、確認、成功四種狀態。
- 驗證建立前「我的案件」不存在該案，建立後出現且數量同步更新。
- 驗證重新整理後 session 狀態仍存在，重設 Demo 後恢復初始狀態。
- 執行 lint 與 production build，並以手機尺寸檢查主要流程。
